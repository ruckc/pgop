## What This Is

`pgop` is a Kubernetes Operator (built with kubebuilder / controller-runtime) that manages PostgreSQL clusters. It exposes three CRDs: `Cluster`, `Role`, and `Database` in the `pgop.ruck.io` API group, `v1alpha1` version.

## Common Commands

```bash
make build          # Build binary (runs manifests, generate, fmt, vet first)
make test           # Run unit tests with envtest (real K8s API + etcd, no Kind needed)
make test-e2e       # Run e2e tests against a Kind cluster (creates/destroys pgop-test-e2e)
make lint           # Run golangci-lint
make lint-fix       # Run golangci-lint with auto-fix
make manifests      # Regenerate CRDs/RBAC from +kubebuilder markers
make generate       # Regenerate DeepCopy methods
make run            # Run controller locally against current kubeconfig context
```

Run a single test file:
```bash
KUBEBUILDER_ASSETS="$(./bin/setup-envtest use --bin-dir ./bin -p path)" go test ./internal/controller/ -run TestSuiteName -v
```

## Auto-Generated Files — Never Edit Directly

- `config/crd/bases/*.yaml` — regenerated by `make manifests`
- `config/rbac/role.yaml` — regenerated by `make manifests`
- `api/v1alpha1/zz_generated.*.go` — regenerated by `make generate`
- `PROJECT` — kubebuilder metadata

After editing `*_types.go` or `+kubebuilder:` markers, always run `make manifests generate`.

## Architecture

**Entry point:** `cmd/main.go` — registers all three reconcilers with the controller-runtime manager.

**API types** (`api/v1alpha1/`):
- `cluster_types.go` — `Cluster` CR: manages a StatefulSet + Service + credentials Secret
- `role_types.go` — `Role` CR: creates a PostgreSQL user/role, references a `Cluster`
- `database_types.go` — `Database` CR: creates a PostgreSQL database owned by a `Role`, references a `Cluster`
- `common_types.go` — shared types: `ClusterReference`, `StorageSpec`, `SecretKeySelector`

**Controllers** (`internal/controller/`):
- `cluster_controller.go` — provisions StatefulSet, headless Service, and a `<name>-credentials` Secret with a generated password. Uses owner references for GC. Requeueing every 10s until StatefulSet is ready.
- `role_controller.go` — connects to PostgreSQL via the cluster credentials secret and issues `CREATE ROLE` / `ALTER ROLE` SQL.
- `database_controller.go` — connects to PostgreSQL and issues `CREATE DATABASE` SQL.
- `constants.go` — shared label keys/values, secret keys, default image (`postgres:18`), default username.

**Resource flow:** `Cluster` → creates StatefulSet/Service/Secret → `Role` reads Secret, connects, creates PG role → `Database` reads Secret, connects, creates PG database.

**Testing:** Uses Ginkgo v2 + Gomega BDD style. Unit tests use envtest (real etcd + K8s API server, no Docker). E2E tests in `test/e2e/` use Kind with a real deployed image.

## Controller Implementation Conventions

- Reconcile functions re-fetch the object first; update status via `r.Status().Update()` separately.
- All owned resources set `controllerutil.SetControllerReference` for automatic GC.
- Controllers watch owned resources with `.Owns()` so mutations trigger re-reconciliation.
- Status uses `metav1.Condition` with `meta.SetStatusCondition`.
- Pods run as UID 999 (postgres), non-root, drop ALL capabilities, RuntimeDefault seccomp.

## Scaffold Rules

- Use `kubebuilder create api` / `kubebuilder create webhook` — do not create scaffold files manually.
- Never remove `// +kubebuilder:scaffold:*` comments; the CLI injects code at these markers.
- RBAC markers live in controller files; markers in `*_types.go` define CRD schema.
